# AI 工程 PR 审查标准

## 审查顺序

先确认问题与变更边界，再沿入口、状态、依赖、错误处理、可观测性和测试逐层检查。审查意见应指向具体风险和可验证的失败场景，不能只给“建议加测试”之类泛化结论。

## 兼容性与状态

配置项必须有稳定默认值和非法值处理。持久化结构、向量维度、Checkpoint 字段和 API 响应变更要说明向后兼容策略。导入、索引与重试操作应满足幂等性；相同输入重复执行不能产生重复状态或破坏既有数据。

## 失败恢复

外部模型、可选依赖和网络调用必须有明确超时。回退策略要区分可恢复错误与配置错误，并保留原始异常。循环与图遍历必须同时具备业务预算和全局转换上限，终止后清理临时状态。安全回退不能偷偷换成语义不等价的算法却继续报告原策略。

## 测试与证据

最低测试集合包括主路径、空输入或无命中、依赖不可用、达到重试上限、回退成功、状态清理和响应字段兼容。检索改动需用固定语料与查询比较 Source Hit、意图、工具选择、证据门控和延迟。测试通过只证明覆盖范围内的行为，不代表生产流量的泛化效果。

## 合并门槛

以下情况应阻断合并：错误被吞掉且无法诊断；重试无界；模型或索引不兼容；回退改变语义却没有暴露；缺少失败路径测试；结论超出已有运行或源码证据。非阻断建议应明确说明收益与后续验证方式。
